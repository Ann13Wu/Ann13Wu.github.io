## 为什么不用纯 CSS

CSS 的 `box-shadow` 可以一次性画几百个点，写起来很爽：

```css
/* 一次生成 100 个星星 */
.stars {
  box-shadow:
    120px 30px #fff,
    480px 210px #c4b5fd,
    /* ... 还有 98 行 */;
}
```

但它有两个硬伤：**不能闪**（每个点都是静态的），**不能动**（要么整体位移，要么就别想了）。想要「会呼吸」的星空，还是得上 Canvas。

## 核心结构

整个星空只有三个图层，从底到顶：

```text
┌─────────────────────────────┐
│  <canvas>  星点 + 流星       │  z-index: -3
│  .nebula   模糊色块（CSS）   │  z-index: -2
│  .grain    噪点质感          │  z-index: -1
├─────────────────────────────┤
│  内容区                      │
└─────────────────────────────┘
```

星云用 CSS 而不是 Canvas，是因为它需要 `filter: blur(70px)` 这种级别的高斯模糊——Canvas 做这个开销太大。让 CPU 专心画星星，让 GPU 专心模糊色块。

## 星点的数据结构

```js
{
  x,  y,    // 位置
  r,        // 半径 0.35 ~ 2.1
  a,        // 基础亮度 0.28 ~ 0.95
  sp,       // 闪烁速度 0.006 ~ 0.028
  ph,       // 初始相位（关键！）
  c,        // 颜色
  vy,       // 漂移速度
  tw        // 是否大星（画十字光芒）
}
```

**相位 `ph` 是让星空看起来自然的关键。** 如果所有星星都用同一个闪烁公式，它们会一起亮、一起暗，像在眨眼——非常诡异。给每颗星一个随机相位之后，它们就各自闪烁了。

```js
var alpha = s.a + Math.sin(t * s.sp + s.ph) * 0.34;
```

## 性能：数量要跟着屏幕走

星星数量不能写死。手机上 400 颗会卡，4K 屏上 100 颗又太稀疏：

```js
var density = Math.round((W * H) / 7200);
density = Math.max(90, Math.min(density, 460));
```

另外两个坑：

- `devicePixelRatio` 要**限制在 2 以内**。3 倍屏下画布像素量是 1 倍屏的 9 倍，肉眼几乎看不出差别，但帧率会掉一半。
- `shadowBlur` 很贵，只给 9% 的「大星」用，其余的直接 `fill()`。

## 最关键的问题：文字可读性

这是星空主题最容易翻车的地方。**背景越梦幻，文字越难读**，而大多数「梦幻风」模板的做法是——把文字调亮一点，然后发现亮到发光反而更糊。

我的解法是三层：

### 1. 面板遮罩

所有文字都在半透明面板里，而不是直接压在星空上：

```css
.panel {
  background: rgba(19, 23, 54, .62);
  backdrop-filter: blur(14px);
  border: 1px solid rgba(167, 139, 250, .22);
}
```

`.62` 这个不透明度是试出来的：低于 `.5` 时星点会穿透文字，高于 `.75` 时背景就白做了。

### 2. 正文不用纯白

```css
body { color: #c9cff0; }   /* 正文 */
h1, h2 { color: #fff; }    /* 标题 */
```

纯白 `#fff` 配长段落会有「光晕感」（视觉上的 irradiance 效应），眼睛很快会累。降一档亮度、加一点蓝紫倾向，反而更清晰。

### 3. 标题的辉光要有边界

```css
h1 {
  text-shadow:
    0 0 26px rgba(167, 139, 250, .55),  /* 梦幻辉光 */
    0 2px 10px rgba(0, 0, 0, .6);       /* 兜底暗影 */
}
```

只加辉光不加暗影，标题在亮星点前会「化掉」。第二层深色阴影是给它兜底的。

## 流星

流星的实现比想象中简单——就是一条**带渐变的线段**：

```js
var g = ctx.createLinearGradient(m.x, m.y, nx, ny);
g.addColorStop(0,   'rgba(255,255,255,.9)');   // 头：白亮
g.addColorStop(0.4, 'rgba(196,181,253,.45)');  // 中：淡紫
g.addColorStop(1,   'rgba(167,139,250,0)');     // 尾：透明
```

触发概率设为 `0.0028`／帧，约等于每 6 秒尝试一次，同时最多存在 2 颗。太频繁会让人分心——毕竟这是背景，不是主角。

## 别忘了 prefers-reduced-motion

```js
var reduced = window.matchMedia &&
  window.matchMedia('(prefers-reduced-motion: reduce)').matches;
```

有些人对动态背景会有眩晕反应。检测到这个偏好时，我关掉了漂移、闪烁和流星，只保留静态星图。**一个星空不该以让人难受为代价。**

## 小结

做视觉的时候我总提醒自己一句话：**氛围是给眼睛的，可读性是给大脑的。** 前者负责让人愿意停下，后者负责让人能待下去。两者缺一个，页面就失败了。
